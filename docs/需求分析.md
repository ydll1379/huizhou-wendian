# 徽州问典需求分析

## 产品定位

徽州问典是面向安徽县乡红色遗存的公益 Web 辅助平台。首期围绕合肥、芜湖、阜阳、淮南等徽州地区，整合公开红色史料，以可追溯问答、研学素材、轻量宣传文案和周边出行信息，帮助原本缺少数字化资源的小型场馆和学校降低内容准备门槛。它是竞赛演示原型和辅助工具，不替代场馆专业讲解，也不承诺为用户提供实时核验过的运营信息。

## 用户与待完成任务

| 用户 | 主要任务 | 产品应交付 |
|---|---|---|
| 研学教师 | 快速备课、给学生讲解、组织本地红色研学 | 可讲授的知识提纲、学生可理解的讲解、现场问题与任务、带出处的路线参考 |
| 红色文化游客 | 临场了解景点、继续追问、安排附近吃住和出行 | 通俗讲解、文献来源、附近餐饮/住宿信息、地图导航和城市路线入口 |
| 基层文旅人员 | 在没有专用讲解硬件和专业内容团队时整理传播材料 | 可复制编辑的景点简介、讲解词、活动预告、公众号/短视频草稿；资料不足时明确留待核实 |

## 共同要求

1. **先可信，再生成。** 回答以知识库资料为依据，显示出处并可查看原文；资料不足时说清楚边界，不补造史实、活动时间、交通或服务信息。
2. **浏览器即可使用。** 当前阶段是轻量 Web Demo，不要求安装 APP 或采购讲解设备；基础公益问答面向游客和学生免费。
3. **场景不同，输出不同。** 三个模式分别服务教学/研学、现场游览、基层传播；教师生成的内容应能转为学生可用语言，宣传稿应能复制后再按当地实际编辑。
4. **路线与周边信息有边界。** 路线按城市候选点位规划，餐饮住宿由地图服务提供；界面需要说明来源、距离/导航和路线覆盖范围，不暗示结果等于官方推荐或实时营业承诺。
5. **保留低门槛反馈。** 用户可以用短文本分别提交史料纠错线索或产品建议，避免复杂问卷；反馈仅用于后续人工核验和迭代。

## 已落地的产品要求

- 三个人群各有快捷任务；教师可设定学段、讲解时长和教学目标，生成课堂讲解、互动问题和现场任务。
- 基层文旅人员可选景点简介、公众号推文、活动预告、短视频口播、讲解词和海报文案；资料库没有的活动信息会提示待补充。
- 回答可复制，引用卡支持来源链接、发布机构、日期、适用地点和页码等元数据；知识库片段保留原始文件路径。
- 路线支持指定起点、终点和必经景点，后端验证景点城市并确保必经点进入结果；站间交通仍由地图服务查询。
- 用户可提交史料纠错和功能建议；本机审核页可标记状态并写备注，审核 API 只允许本机请求。
- 首期四城试点和更广泛的景点注册表分别表述，避免把试点范围误读成唯一覆盖范围。

## 仍需持续完善

- 当前旧索引已补上 184 个片段对应的原始文件路径。原始资料暂未提供可识别的来源 URL、发布机构和页码；补充资料 front matter 后需重新建库，不能可靠推断的字段保持为空。
- 路线的起终点和必经点目前是单城市、最多 6 个注册景点的路线约束，地图定位失败时会明确报错；行程时间、开放状态和预约要求仍需用户向场馆核实。
- 当前反馈保存在应用本机 JSON 文件中，适合演示原型；多人部署需要迁移到有访问控制的持久化数据库和账号权限体系。
- 用户研究和知识库资料采集仍需严格区分。计划书提到的需求访谈/点位走访不代表相关口述资料已进入当前知识库。

## 资料来源元数据格式

在 Markdown 资料开头可选用 YAML front matter：

```yaml
---
source_url: https://example.org/source
publisher: 发布机构
published_at: 2024-01-01
site: 适用景点或地区
page: 12
---
```

缺失字段可省略；不要推测补齐。建库脚本会把这些字段附加到对应文本分块中。

## 依据

上述定位和用户任务来自《徽州问典项目计划书》的项目背景、典型客户、产品服务、市场痛点和受众分析章节。计划书明确将当前阶段描述为公益参赛 Web Demo；商业收费、规模化部署和终端扩展均属于远期设想，因此本轮不把这些设想实现成当前承诺。

计划书在项目背景中提到需求访谈和少量点位走访，在产品说明中又写明知识库素材来自公开网络资料、没有线下采集。后续对外介绍应明确区分“用户需求调研”和“知识库史料来源”，避免让人误以为口述/实地资料已进入知识库。
